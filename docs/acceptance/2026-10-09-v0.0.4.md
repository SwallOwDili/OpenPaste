## P2 捕获、持久化与边界

- 状态：部分通过（本机，候选 rc3 解压副本，隔离 profile）。
- 冷路径：空数据目录启动，测试目标 PasteFixture 依次复制文字、富文本、颜色、代码、PNG 图片、链接、文件引用。`history.json` 中七类均按复制顺序新增在最前，类型正确（富文本含 `public.rtf`，文件为 `public.file-url`，图片为 `public.png`）。
- 去重：再次复制同一段文字，条数不变，该条回到最前。
- 重启持久化：重启前后 10 条历史的 ID 与大小逐条一致；多出 1 条是启动时记录的当前剪贴板（来源“当前剪贴板”）。
- 边界（用本机脚本写系统剪贴板，等待足够时间后读取 `history.json`）：
  - 敏感标记 `org.nspasteboard.ConcealedType`、临时标记 `TransientType`：内容不进历史（全文检索不到）。
  - 单条 20 MB 上限：8 MB 记录，19,922,953 字节记录，21 MB 拒绝，之后的普通文字正常记录。
  - 快速连续写入 A、B、C（无间隔）只记录最后的 C，符合“快于 0.3 秒轮询的连续复制允许漏掉中间内容”。
- 观察（不判定为缺陷，需决定是否可接受）：处理 6 MB 以上内容需要超过 1.5 秒；此期间若又有新的复制，前一次大内容的采集被作废而不入历史（第一轮 6 MB、19 MB 间隔 1.5–2 秒写入时被丢失，间隔 12 秒时正常）。另有一次紧接启动后写入的普通文字（`BOUNDARY-NORMAL-1`）未被记录，复测同类写入正常，原因未定位。
- 未执行：组合筛选与搜索、收藏分组 GUI、暂停/定时到期、1,000/7,500 条下的方向键。

5. 候选会记录验收期间系统里的所有复制，验收数据目录含用户操作痕迹，仅在本机 `build/acceptance/`，未入库。

## 发布产物核验与发布结论

### rc3、rc4 最终公开产物（2026-10-09，本机）

发布工作流同时监听 `release: published`，上传步骤使用 `--clobber`。因此对草稿先手动构建再发布时，发布动作会触发第二次构建并覆盖同名安装包；草稿阶段核验的文件不是最终公开的文件。实测：

| 版本 | 草稿阶段 ZIP / 可执行文件 / 构建号 | 最终公开 ZIP / 可执行文件 / 构建号 |
| --- | --- | --- |
| v0.0.4-rc3 | `3a41dd6b…` / `853e514b…` / 15 | `c83a0a84…` / `5c9eea00…` / 16 |
| v0.0.4-rc4 | `7d392d68…` / `28a73d66…` / 17 | `b731f323…` / `a3332cc2…` / 18 |

两次构建源码（同一 tag）和签名证书相同，字节不同（构建号为 GitHub 运行编号）。已对**最终公开**的 rc3、rc4 重新核验：SHA-256 与校验文件一致，`codesign --verify --deep --strict` 通过，签名要求为 `certificate leaf = H"7127ce07d64e527592676bab61d383ecb5d4d270"`，架构 `x86_64 arm64`，无 `--update-test` 测试入口，版本与 tag 一致。下载计数：rc1 的 ZIP 与校验文件各 2 次，rc2、rc3 为 0，覆盖期间无外部下载记录。该流程问题经用户决定暂不修改；v0.0.4 采用“直接发布，由 `published` 触发唯一一次构建”，只核验最终产物。
