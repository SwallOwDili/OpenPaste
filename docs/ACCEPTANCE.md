# 发布前功能验收

2026-10-08 本轮补测范围：定位并消除 7,500 条初始历史安装的重复筛选/发布，记录优化前后同步和主循环停顿；裁剪仍须保留收藏、容量和时间边界语义。使用系统 CGEvent 驱动真实全局快捷键，验证专用目标内 Return、Shift-Return、连续取用及目标切换，按目标实际收到的内容和次数判定。用户明确排除本轮 iCloud 验收，不将其计入本轮完成范围。

本文把 README 中的产品声明转换为发布前验收项目。每条结果必须使用以下四种状态之一，并写明实际验证层级：

- **已通过（单元 / 本机 / GUI / 外部）**：本版本已实际执行，结果符合预期，且附有证据。只通过单元检查时只能标“已通过（单元）”，不能代表 GUI 或外部集成通过。
- **失败**：已执行但实际结果不符合预期；记录复现步骤、影响、日志和缺陷链接。
- **待实测**：尚未执行。可附注“已有单元覆盖”，但不能写成通过。
- **环境阻塞**：因缺少明确外部条件无法执行，例如 Intel 实机、第二台 Mac、正式签名或用户翻译服务；记录所缺条件、责任人和解除方式。

当前矩阵只陈述已知覆盖入口和待实测范围，不代表本版本结果。不得仅凭源码存在、历史记录或相邻测试通过修改为“已通过”。每次验收应记录候选版本、commit、macOS 版本、CPU 架构、签名类型、测试账户、执行日期和证据位置。

## 测试层级与外部条件

| 标记 | 含义 |
| --- | --- |
| 单元 | 无窗口逻辑或本机模拟服务；由 `scripts/unit-tests.sh` 和 `scripts/check.sh` 执行 |
| 本机 | 使用真实本机数据格式、文件系统、剪贴板或安装包，但不依赖第二台设备 |
| GUI | 在前台桌面启动候选 App 并操作真实窗口 |
| 外部 | 依赖公开网络、用户翻译服务、Firebase、第二台 Mac 或其他目标应用 |
| 辅助功能 | 需要 macOS“辅助功能”及按键事件权限 |

## 隔离桌面验收入口

普通实例先退出，然后从仓库根目录执行：

```sh
./scripts/build-paste-target.sh
open build/acceptance-tools/PasteFixture.app
profile=$(uuidgen)
OPENPASTE_ACCEPTANCE_ROOT="$PWD/build/acceptance/$profile" \
  build/OpenPaste.app/Contents/MacOS/OpenPaste --acceptance-profile "$profile"
```

验收实例的启动方式有两条限制，2026-10-09 实测：一是不能用 `open` 启动，隔离校验要求当前工作目录为仓库根（`build/acceptance/<uuid>` 的上级），`open` 启动的工作目录是 `/`，进程会在启动时断言终止；二是从 shell 或代理工具直接运行二进制时，系统可能把辅助功能与按键事件权限算到启动者头上，表现为“权限未生效”、取用后只复制不粘贴。需要验证直接粘贴时，用 `Tests/Support/SpawnDisclaimed.swift` 编译出的启动器脱离责任进程：`swiftc -O Tests/Support/SpawnDisclaimed.swift -o build/acceptance-tools/spawn-disclaimed`，再在仓库根执行 `OPENPASTE_ACCEPTANCE_ROOT="$PWD/build/acceptance/$profile" build/acceptance-tools/spawn-disclaimed "$PWD/<App 路径>/Contents/MacOS/OpenPaste" --acceptance-profile "$profile"`，使 OpenPaste 以自己的签名身份取得已有授权。验收期间候选会记录系统里的任何复制，数据目录含操作痕迹，只留在本机。

同一 profile 重启会保留验收历史与设置；新 UUID 表示新安装。该模式仍运行真实捕获与保存流程，但使用专用数据与偏好配置，关闭统计和个人 Paste 数据自动发现。不要在验收实例中填写真实 Key。粘贴目标只有在启动时取得完整剪贴板快照、退出时剪贴板仍保持该目标最后一次写入的修订时，才会尝试写回启动前内容；快照不完整或测试期间有其他进程复制新内容时保留当前剪贴板。无论是否尝试恢复，退出后都须核对实际剪贴板状态。

验收模式日志中的 `next-turn-ms` 是同步操作到下一次主队列执行的耗时，拆成 `sync-ms` 与 `queue-ms`；`main-loop max-delay-ms` 是每 5 秒窗口内 20 ms 定时器的最大迟到，`max-turn-ms` 是主循环从唤醒到再次等待的最长时间，另记发生时间与 RunLoop mode。定时器迟到不一定表示应用代码阻塞；长主循环也可能包含 AppKit、系统文件提供者或桌面工具操作，需结合调用栈定位。上述指标都不是精确屏幕绘制延迟。超过 100 ms 的交互停顿需定位并复测，磁盘/网络长任务另记总耗时，不能阻塞核心操作。启动单独记录 `launch.store-init`、`launch.panel-host` 与 `launch.delegate-tail-ms`，不得把冷启动和热操作混算。

## 自动逻辑门禁

两个发布前脚本都应执行所有明确归类为无 GUI 的逻辑入口。入口一致性由 `Tests/test_entrypoints_unit_test.py` 检查；真实 Paste 数据检查及所有 GUI 检查明确排除在自动逻辑门禁之外。

自动入口使用临时目录或测试夹具。`--current-clipboard-test` 使用独立命名剪贴板，但 `Store` 初始化仍会读取系统剪贴板 change count；测试进程不读取或替换真实剪贴板内容。`--drag-provider-test` 会写临时拖放文件。真实 GUI 验收使用下文的专用 profile；`CFFIXED_USER_HOME` 只改变部分 Foundation 路径，不能单独作为 UserDefaults 和配置文件隔离的证据。

### P0：候选版本与环境基线

设置侧栏点击范围回归：对通用、快速翻译、隐私与权限、数据管理、关于五项，分别从其他页面点击整行右侧留白、图标与文字左侧留白、上/下内边距，核对对应标题与内容切换；选中后点击同一区域保持当前页，点击行间间隙不切换。必须使用窗口截图定位真实鼠标坐标，不能用无障碍按钮激活代替命中范围验收。记录候选二进制、坐标、预期页面与实际结果。

菜单收起回归：冷启动首次呼出后点击右上角“更多”，菜单与面板应同时保持；按 Esc 只关闭菜单，方向键仍可选择卡片。再次打开并点击“设置…”，应显示设置窗口后再隐藏面板；菜单打开时点击其他应用，应正常收起。连续重复打开/取消、右键卡片和嵌套菜单，确认没有误关、卡住或焦点丢失。必须操作真实菜单，不能只调用控制器方法。检查日志的 `menu.begin`、`menu.end`、`shelf.hide` 及原因；生产日志在 `~/Library/Logs/OpenPaste/OpenPaste.log`，验收日志在对应 profile 的 `Logs/OpenPaste/`，禁止记录剪贴板正文、密钥和窗口标题。首次及重复操作分别记录耗时和实际结果。

1. 记录 commit、`git status`、候选版本、签名类型、ZIP SHA-256、macOS 版本、硬件型号和 CPU 架构。
2. 建立独立测试账户和专用数据目录；保存原剪贴板内容，确认普通 OpenPaste 实例已退出。
3. 准备固定夹具：短文字、含中文/Emoji 的长文字、RTF、代码、合法/非法颜色、公开 HTTPS 链接、Apple 地图链接、PNG/TIFF/GIF/HEIC、有效和失效文件引用。
4. 准备三档历史量：冷启动空库、热启动 1,000 条、压力档 7,500 条；记录附件总大小。
5. 启动计时或屏幕录制。每项记录总耗时、首个可见结果时间和最大无响应停顿；未事先定义产品阈值的项目记录观察值，不擅自宣称性能通过。

新复制与批量 OCR 刷新次数回归：新复制一条内容（含触发裁剪与不触发裁剪两种）只能发布一次历史并只做一次筛选与来源重建；批量 OCR 按批写回，N 张图片不得产生 N 次整表重算；未裁剪任何内容时不得重新赋值历史。同时核对内容仍按指纹去重、保留收藏与自定义名称、容量与条数裁剪边界不变，OCR 结果在条目被删除或内容变化后不写入。以 7,500 条夹具记录复制一条后的主线程停顿（改前改后）；该指标不是屏幕绘制延迟。

冷启动后台读取耗时回归：以同一份 7,500 条夹具（约 7,500 个附件）冷启动，记录 `history.initial-load.background` 总耗时，改动前后各至少 3 次并写明冷/热状态；附件读取不得对每个附件重复做目录判定、符号链接解析或文件系统元数据探测。本地（非 iCloud）目录与 iCloud 目录分别验证：缺失附件、大小不符、符号链接指向其他位置及 iCloud 占位文件仍须报错并保持只读保护，不得因提速放宽校验。用 `sample` 取得有效主线程与持久化队列调用栈，列出前几项耗时占比，不以重复整套测试代替定位。摘要（SHA-256 十六进制）输出须与旧实现逐字节一致。

冷启动历史读取回归：7,500 条附件历史必须在后台完成完整校验；读取期间设置和退出仍可响应，但记录、历史修改、导入、迁移、同步与保存不能写入未加载的空历史。完成后一次安装完整结果，暂停期间的剪贴板不能补录。分别验证慢读取、读取失败、旧回调失效及加载中退出；原文件和设备清单不得被空历史覆盖。分开记录主线程初始化、后台加载总耗时和最终安装耗时。

预期：候选二进制、源码 commit、环境和证据可一一对应。本地未提交候选需保存差异与源码快照哈希；只有二进制来源不明或夹具包含私人数据时才阻塞验收。未提交候选的结论不能直接替代最终提交/安装包的发布结论。

### P1：自动逻辑门禁

1. 运行 `scripts/unit-tests.sh`（内部使用专用剪贴板、目录及模拟服务），保存完整日志、退出码和耗时。
2. 在候选源码上运行 `scripts/check.sh`；确认日志显示重新构建当前源码，而不是复用已有 App。
3. 核对 `Tests/test_entrypoints_unit_test.py` 成功分类所有 executable 检查参数，并确认两个脚本执行完全相同的无 GUI入口集合。
4. 核对 localhost 翻译 fixture 启动、请求和关闭均成功；确认没有调用用户翻译服务。
5. 任一检查非零退出时，记录首个失败、后续是否未执行及复现命令，状态记为“失败”。

预期：两个脚本均执行版本、Python unit、全部无 GUI Swift 入口和 localhost 翻译检查；GUI 与真实 Paste 数据入口不应被自动调用。一次成功只允许相关条目标记“已通过（单元）”。

### 本轮修复验收补充（2026-10-08）

- 暂停恢复只记录之后的新复制：暂停时复制 B，手动恢复、定时到期、重启后到期或过期后启动，均不得补录 B；立即呼出面板的强制捕获也不得补录，随后复制 C 应正常记录。覆盖用户暂停与存储故障、临时暂停重叠；不得使用真实密码作测试内容。
- 读取失败时允许明确选择其他可读目录或默认目录恢复：先完整读取目标再切换，原目录、目标已有历史和附件保持完整，不合并失败来源的残缺内存历史；目标同样损坏时保留原状态并说明原因。迁移任意目录枚举错误必须中止，包含仅中间一次枚举失败且存在未同步缓存的情形。
- 链接预览回调在历史只读时不能修改内存或磁盘；恢复后正常更新，条目删除或网址编辑后旧结果不得写回。内网后缀、IP、敏感参数和疑似一次性链接不得自动加载；普通公开网页预览保持可用。分别验证判定与真实请求，规则测试不能冒充完整网络隔离。
- 快速翻译设置明确区分读取选区与直接粘贴权限，权限缺失时有状态和授权入口，恢复授权后状态更新；不在剪贴板底部恢复常驻权限文案。翻译只使用已保存配置，未保存修改和其他配置域不得串入请求。
- 首次启动披露默认使用统计并提供独立关闭入口，保持统计与启用本地记录相互独立；无 Firebase 配置构建不能宣称已验证真实统计。
- 迁移和导入期间，已打开编辑器的保存、重命名、收藏与迟到预览回调均不得改写历史；结束后恢复可写。导入解析和提交期间记录状态应明确显示暂停，取消或失败后恢复原暂停归属。
- 导入只能更新所属配置域。正式包不得包含测试命令和测试实现；专用验收包保留自动化入口，使用独立产物和缓存目录。单元、故障注入、GUI、正式产物检查分开记录结果。

### P2：捕获、搜索、筛选、收藏与记录控制

本轮恢复回归：首次选择“暂不启用”后，设置和菜单应提供“启用记录”，重新启用不得清除已有的数据故障或用户暂停。使用缺失附件的专用历史并移除验收配置中的启用标记，点击启用、修改上限和尝试新建后，原索引及其余附件的哈希必须不变；修复夹具后，通过“重试读取”恢复原历史。使用专用不可写目标制造保存失败，恢复可写条件后“重试保存”应保留内存内容并恢复正常记录；原本用户暂停的仍保持暂停。覆盖连续失败、重复重试、恢复后迟到的旧回调及切换目录后的旧回调。只读失败与写入失败不得相互解除。

1. **冷路径**：清空专用数据目录后启动，明确接受本机记录；依次复制短文字、链接、RTF、PNG/TIFF、文件和多 item 内容，每次等待超过轮询间隔。
2. 核对卡片类型、顺序、原始格式和重启持久化；来源按捕获时的前台应用推断，正常稳定前台场景应一致，并另记录切换应用与轮询交叠时的实际来源，不能据此宣称始终准确。再次复制同一内容，核对去重及名称/收藏保留。
3. 对标题、正文、来源和 OCR 分别搜索；依次组合类型、来源、今天、日期范围和收藏筛选，记录期望 ID 列表与实际 ID 列表。
4. 创建两个不同颜色收藏分组，执行收藏、取消、跨组、删除分组和重启；核对条目与成员关系。
5. **用户无限暂停与重启**：在正在记录的验收 profile 中复制唯一标记并确认进入历史；选择“直到手动恢复”，再复制第二个标记并确认未记录。修改一个可辨认的无关设置后从 App 内退出，使用同一 profile 重启；在“隐私与权限”确认仍显示暂停、无关设置仍保留，复制第三个标记并确认仍未记录。点击“继续记录”，复制第四个标记并确认进入历史。分别记录退出前、重启后、手动恢复后三个状态，不能只凭按钮文字推断捕获结果。
6. **真实定时到期**：选择“5 分钟”，记录点击完成的墙上时钟时刻，并以该时刻加 5 分钟作为原到期时刻；在到期前退出并用同一 profile 重启。到期前复制唯一标记并确认不记录，持续保持 App 运行并等待超过原到期时刻，再确认界面恢复记录且新的唯一标记进入历史。另设一次“5 分钟”，立即退出并保持 App 关闭直到原到期时刻之后，再用同一 profile 重启，确认直接恢复记录。不得改系统时钟，也不得以受控时钟单元检查代替这两次真实等待；定时跨重启未实际执行时保持“待实测”。
7. **受控时钟与并发原因组件检查**：通过自动逻辑门禁中的 `--recording-pause-test` 验证未来截止时间按绝对时间保存、过期状态启动时清除、续设定时暂停替换旧截止、无限暂停与定时暂停互相替换、旧或已取消的 timer token 不能恢复较新的暂停，以及用户、数据处理临时暂停和安全暂停互不误清。此项只能标“已通过（单元）”；真实 `Timer` 调度、退出重启和界面状态仍按第 5、6 步记录。

4. **边界**：重复导入、损坏行、外部载荷、路径穿越、图片多表示、容量预算、超历史条数及大数据集。
5. **失败恢复**：导入中断、只读目标、空间不足、附件缺失；核对活动索引、导入前备份和源数据的实际可读状态，记录可能遗留的备份或未引用附件；修复条件后重复运行，核对不会重复新增已提交条目。
6. 记录冷首次导入、重复导入、记录数、字节数、总耗时和最大停顿。

预期：每条源记录均被导入、判重或明确计入失败类别；应用报告成功前必须能重新读取新活动索引。进程或系统写入中断时以活动索引和附件实测为准，不把原子索引写入等同于整个导入目录无任何中间产物。

### P8：数据目录与双 Mac iCloud

1. 在本机专用源目录准备已知历史，目标目录准备不同历史；通过 GUI 迁移并核对合并、备份、进度、切换和重启读取。
2. **边界**：选择源目录子目录、损坏目标、只读目标、空间不足和 7,500 条数据；确认非法目标不会切换。
3. 两台同账户 Mac 选择同一专用 iCloud 目录；依次验证 A 新增、B 下载、B 编辑/收藏、A 合并、离线新增、并发删除和重新上线。另用仅 A 存在的文件路径建立文件条目，确认 B 只得到路径引用且明确显示无法访问，不能把文件本体未同步记为历史同步失败。
4. 模拟或等待系统占位文件状态，确认未下载清单时不清理共享附件；确认本机缓存仍可安全回收。
5. **失败恢复**：迁移或同步中断后核对当前选择仍指向原目录，并分别检查源目录、目标目录已写入内容、目标原索引备份和本地缓存；恢复联网后继续合并，核对明确删除项未被旧设备复活。
6. 记录两机型号/系统、数据量、上传/下载/合并时间和最大停顿，并分别保存两端索引证据。

预期：本地迁移仅在目标写入并校验成功后切换当前目录，源目录保留；目标原先存在活动索引时应生成迁移前备份。迁移失败可能在目标留下备份、附件或暂存文件，不能写成整个目录事务回滚。iCloud 行为必须以两台实体 Mac 的结果记录，模拟结果只能标“已通过（单元）”。

   Analytics 候选须遵循所用 SDK 的链接要求（包括 `-ObjC`）；分别记录本地入队、成功上传、调试模式生效和控制台收件证据。成功上传不等于 DebugView 已显示，普通批次不能当作调试事件；验收后恢复原统计偏好并关闭调试模式。

### P11：长期运行、周期操作与恢复

1. 使用与发布结论相同的候选产物和独立 profile，导入 7,500 条专用历史并准备文字、富文本、图片、文件、网页和 OCR 夹具。记录开始时刻、历史与附件数量、活动数据目录、收藏与设置快照、进程内存和连续性能日志位置。
2. 默认连续运行至少 4 小时；若本次计划采用更长时长，执行前写入版本记录，不能在看到结果后缩短。少于计划时长只能记录实际观察并保持“待实测”，一次 4 小时检查也不能表述为无限期稳定。
3. 每 15 分钟执行一轮固定操作并给夹具标记轮次：复制新的唯一文字并确认捕获，呼出面板，搜索该标记，组合一种类型或收藏筛选，连续方向移动 20 次，预览文字与图片各一次，编辑并保存一条文字，切换一次收藏，将两条内容加入队列并逐条取用，打开和关闭设置。4 小时默认应保存 16 轮结果，不得用最后一轮成功代表中间轮次。
4. 每小时执行一次图片 OCR 和一次允许联网的公开网页预览；依次记录首次与缓存命中结果。中途关闭联网预览一次，再重新开启并验证后续新请求恢复；网络失败不得影响本机历史操作。
5. 在运行中段执行一次系统睡眠再唤醒；唤醒后核对记录状态、全局呼出、最新历史和计时日志继续工作。有多显示器条件时，再将菜单栏、目标应用与面板分别放到不同显示器并完成一轮；没有对应条件时只把多显示器子项标“环境阻塞”。
6. 每小时及结束时记录历史与附件数量、进程内存、CPU 观察值、主循环最大迟到与最长 turn、磁盘占用和任何超过 100 ms 的可见停顿。项目尚未定义资源增长阈值时记录曲线和峰值，不因单个最终数值宣称“无泄漏”；持续增长、界面恶化或磁盘无界增长须保留证据并定位。
7. 到达计划时长后从 App 内退出并用同一 profile 重启，逐轮核对唯一标记、编辑、收藏和队列结果，确认数据目录与设置未重置；再执行一次捕获、搜索、预览和保存。只有预定轮次、重启后数据和核心操作都符合预期，才可将本次时长标“已通过（GUI）”。
8. 若发生崩溃、假死、无法退出或数据异常，先保存崩溃报告、最后一段应用日志、发生时刻、最后完成轮次和资源样本，再重启核对最后已确认保存的数据及活动索引。记录丢失范围和恢复结果，修复后须在新候选上重新完成原定时长，不能从失败时刻续算。

预期：计划时长内无崩溃、假死或历史损坏，各轮操作结果一致，睡眠、网络切换和重启后核心功能可恢复。结论只覆盖实际候选、实际环境和记录的持续时长。

## 新功能进入发布验收的流程

新增或改变用户可见功能时，必须在合并前建立以下闭环，并在每版本记录中保留从声明到结果的对应关系：

1. 把产品声明关联到本矩阵和操作规程中的固定验收 ID；现有章节无法覆盖时再新增功能章节，不能只更新 README。
2. 在执行前写定正常路径、输入/容量/时序边界和失败恢复的夹具、逐步操作、预期结果、数据量及冷/热条件。执行中不得为迁就实际结果改写原预期；产品声明或实现确需调整时，记录调整原因并重新开始该用例。
3. 将可确定性验证且不需要窗口的逻辑加入无 GUI 测试入口，并在 `Tests/test_entrypoints_unit_test.py` 中分类；需要 GUI、真实用户数据或外部系统的检查明确归入对应层级，不能混入自动门禁。
4. 在同一候选 commit 和对应产物上执行所需层级，逐项填写实际结果、耗时、最大停顿和可追溯证据。只执行单元检查时只能标“已通过（单元）”；未执行层级保持“待实测”，缺少明确条件时标“环境阻塞”并写清责任人、发布影响和解除条件。
5. 实际结果不符合预期时标“失败”并关联缺陷；修复后生成新的候选基线，原样重跑失败用例及受影响的关联用例，保留修复前后证据，填写“修复后回归”和“关联功能回归”。不能只凭代码修改或相邻测试通过关闭失败。
6. 只有重跑通过的层级才能改为“已通过（对应层级）”。最终 ZIP 还需执行 P10；源码构建或中间 App 的结果不能沿用为最终产物结论。模拟结果只能证明模拟层级，不能替代 GUI 或外部集成结果。

## 发布结论规则

以下任一项未完成时，不得写“README 全功能通过”：

1. 自动逻辑门禁尚未在候选源码上完成且结果未保存。
2. 粘贴队列 GUI、系统全局快捷键、跨应用自动粘贴、真实拖放和常用目标应用格式矩阵尚未实测。
3. 用户翻译服务、真实 Paste 数据或真实 GitHub Release 路径中，本次发布承诺覆盖的项目尚未实测。
4. 双 Mac iCloud、Intel 实机、macOS 14、Developer ID 或公证等外部条件尚未实测，却被发布说明宣称已验证。
5. 正式候选 ZIP 的架构、签名、版本、资源、解压完整性和 SHA-256 尚未从最终产物反向核验。

无法取得外部条件时，应在发布记录中保留“待实测”和具体风险，不得用单元模拟替代真实系统结论。
